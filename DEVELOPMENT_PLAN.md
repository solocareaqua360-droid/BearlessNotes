# План розробки MVP

Цей файл — робочий трекер прогресу. Онови статус (☐ → ☑) після кожного
завершеного етапу. Рекомендований підхід: не переходити до наступного
етапу, поки поточний не працює стабільно й видимо — це головний захист
від "розповзання" обсягу, про яке ми говорили на прикладі AFFiNE.

Кожен етап дає щось видиме й перевірне — це і є спосіб "вчасно
коригувати": якщо на якомусь етапі щось відчувається не так, це видно
одразу, а не після місяців роботи.

## Етап 0 — Підготовка проєкту

- [x] Ініціалізувати React Native проєкт (Expo — простіший старт для
      вайб-кодінгу, дозволяє тестувати через Expo Go без збірки)
- [x] Підключити Firebase проєкт (Spark/безкоштовний план), увімкнути
      Firestore і Authentication — проєкт `bearless-notes` створено,
      Firestore (test mode, регіон eur3) і Authentication (Email/Password)
      увімкнено, Web-застосунок зареєстровано, SDK підключено в
      `src/firebase.ts` (конфіг береться з `.env`, див. `.env.example`)
- [x] Покласти `PROJECT_BRIEF.md` у корінь репозиторію
- [x] **Перевірка:** застосунок запускається на телефоні через Expo Go,
      показує порожній екран — підтверджено на реальному Android-пристрої
      користувача (SDK 57.0.0 співпав, застосунок відкрився)

## Етап 1 — Список документів (без реального контенту)

- [ ] Екран списку з порожнім станом (велика іконка + "Створити
      документ")
- [ ] Створення документа (поки що без вмісту) і поява його в списку
- [ ] Видалення документа
- [ ] Нижня навігаційна панель (Документи / Пошук / Календар / Більше —
      інші вкладки можуть бути заглушками)
- [ ] **Перевірка:** можна створити й видалити кілька документів, список
      оновлюється

## Етап 2 — Синхронізація зі сховищем

- [ ] Документи зберігаються у Firestore, а не лише локально
- [ ] Дані з'являються знову після перезапуску застосунку
- [ ] **Перевірка:** видалити застосунок з телефону, встановити знову
      (чи через Expo Go), увійти — документи на місці

## Етап 3 — Редактор документа (базові блоки)

- [ ] Створення текстового блоку через Enter
- [ ] Перетягування блоків для зміни порядку
- [ ] Видалення блоку
- [ ] Автозбереження у фоні
- [ ] **Перевірка:** написати документ із 5+ блоками, переставити їх
      місцями, закрити й відкрити знову — все на місці

## Етап 4 — Розширений редактор

- [ ] Undo/redo з кількома кроками
- [ ] Форматування тексту (жирний, курсив) на рівні блоку і слова
- [ ] Меню швидкого додавання через "/" (список, чекбокс, зображення,
      роздільна лінія)
- [ ] Додавання зображення як блоку
- [ ] **Перевірка:** усі формати з меню "/" працюють, undo коректно
      скасовує кожен тип дії

## Етап 5 — Bypass-конвертація в об'єкти бази даних

- [ ] Мінімальна модель типів об'єктів (справи, нагадування, зображення,
      файли, посилання — з розділенням на звичайне/маршрут/YouTube/TikTok)
- [ ] Конвертація блоку в об'єкт із підтвердженням і undo/redo
- [ ] Перегляд і редагування властивостей об'єкта
- [ ] Видалення об'єкта з попередженням про згадки в документах
- [ ] **Перевірка:** конвертувати запис у "справу", побачити її в списку
      справ, видалити — попередження показує документ, де вона згадана

## Етап 6 — Режими масового вибору

- [ ] Масовий вибір документів (видалення, тег, переміщення)
- [ ] Масове редагування об'єктів бази даних
- [ ] Експорт документів у PDF (один або кілька)
- [ ] **Перевірка:** вибрати 3 документи, застосувати тег до всіх одразу

## Етап 7 — Офлайн-режим і резервне копіювання

- [ ] Доступність без інтернету: поточний, нещодавні, примусово
      закешовані документи
- [ ] Візуальне тьмяніння незакешованих файлів
- [ ] Обробка помилки збереження (тиха повторна спроба → повідомлення)
- [ ] Резервне копіювання документів на Google Диск користувача
- [ ] **Перевірка:** увімкнути режим польоту, відкрити недавній документ
      — працює; відкрити давно не відкритий — видно, що недоступний

## Етап 8 — Полірування під дизайн

- [ ] Перенести кольорову палітру й форму іконок з фінального
      Figma-макета
- [ ] Округлі "сквіркл" іконки, нижня панель дій у зоні досяжності пальця
- [ ] Перевірка стилю на реальному пристрої (не лише в симуляторі)

## Етап 9 — Перший реальний тест використання

- [ ] Тиждень щоденного використання застосунку замість Craft для
      реальних нотаток
- [ ] Список знайдених незручностей і багів
- [ ] Рішення: що виправляти зараз, що відкласти на версію після MVP

## Свідомо відкладено на після MVP (не чіпати, поки Етап 9 не пройдено)

- Дошка (канвас, рамка А4, магнітне групування)
- Довільні типи об'єктів, створювані користувачем
- Пов'язані бази даних (письменники ↔ книги)
- Веб-версія
- Візуальний щоденник з гортанням прев'ю
- Два екрани Fold (зовнішній/внутрішній) — MVP тестується як звичайний
  застосунок на одному екрані
