# BearlessNotes — video-bookmark-app

Особистий кросплатформний буркмарк-менеджер для збереження посилань на
YouTube/TikTok відео з прев'ю, ієрархічними тегами та статусами перегляду.

## Технічне завдання

### 1. Загальна ідея
Особистий буркмарк-менеджер для збереження посилань на YouTube і TikTok
відео з прев'ю, тегами та статусами перегляду. Платформи: iOS, Android,
веб. Перша версія — для власного використання, без монетизації.

### 2. Зберігання даних, синхронізація, акаунт
Офлайн-перший підхід: посилання завжди зберігаються локально на пристрої,
застосунок повністю працює без інтернету і без акаунту. Хмарна база даних
(Firebase або Supabase) для синхронізації між iOS/Android/веб, коли акаунт
підключено. Вхід через Google акаунт. Синхронізація автоматична у фоні. У
налаштуваннях — час останньої синхронізації і кнопка вийти.

### 3. Додавання відео
Через кнопку "поділитися" з YouTube/TikTok, або вручну кнопкою "плюс".
Прев'ю, назва, тривалість підтягуються автоматично за посиланням. Одразу
можна обрати статус і теги.

### 4. Теги
Ієрархічна структура за прикладом Bear (вкладені теги через слаш),
максимум 10 рівнів вкладеності. Одному відео — декілька тегів. У кожного
тега — власна іконка і колір (обирається при створенні або пізніше в
редакторі тегів). Розділ "Inbox" (нові відео) і "Невідсортоване" (відео
без тегів). При видаленні тега — запит: видалити пов'язані відео чи
перенести в невідсортоване.

### 5. Статуси перегляду
"Планую подивитись", "Переглянуто" (можливий третій статус пізніше).

### 6. Головний екран
Плиткова стрічка карток на всю ширину. Кожна картка: прев'ю-зображення
16:9 (іконка плей по центру, тривалість у правому нижньому куті), під
зображенням назва відео жирним шрифтом, нижче теги-пігулки. Зверху
фільтр-пігулки (Усі / Планую подивитись / Переглянуто), пошук. Знизу —
плаваючий острівець-капсула по центру (не на всю ширину) з 4 круглими
кнопками: меню тегів, пошук, плюс (акцентна кнопка), фільтри.

### 7. Бокове меню тегів
Висувна панель зліва. Зверху пошук по тегах. Список: батьківські теги зі
стрілочкою розгортання і кількістю відео праворуч, вкладені підтеги з
відступом зліва. Внизу кнопка "Новий тег". У режимі фільтра — чекбокси
замість стрілочок, обрані теги збираються в чіпи над кнопкою "Показати N
відео". Множинний вибір тегів.

### 8. Форма додавання відео
Зверху "Скасувати" / "Нове відео" / "Зберегти". Поле вставки посилання.
Картка з автопідтягнутим прев'ю, назвою, тривалістю. Вибір статусу — дві
пігулки-перемикача в ряд. Теги внизу з кнопкою додати новий.

### 9. Вкладка перегляду відео
Зверху назад / "Відео" / іконка зовнішнього посилання (перехід у
YouTube/TikTok). Плеєр 16:9 з кнопкою плей по центру. Нижче назва відео,
перемикач статусу (дві пігулки), теги з кнопкою додати, невелике текстове
поле коментаря. Дві опції поведінки при натисканні на відео зі стрічки
(обирається в налаштуваннях): перехід одразу в YouTube/TikTok, або
відкриття цієї вкладки.

### 10. Налаштування
Блок акаунту Google (іконка, email, час синхронізації, кнопка "Вийти").
Перемикач теми — 3 сегменти (Світла/Системна/Темна). Перемикач способу
відкриття відео (У застосунку/YouTube-TikTok) — 2 сегменти. Список:
"Редагувати теги" (стрілка вперед), "Невідсортоване" (лічильник відео).

### 11. Редактор тега
Зверху "Скасувати" / "Редагувати тег" / "Готово". Велика іконка-прев'ю
тега (квадрат із заокругленими кутами, кольоровий фон) поруч із полем
назви. Нижче сітка іконок 6 в ряд для вибору іконки тега. Ще нижче ряд
кольорових кружечків для вибору кольору тега.

### 12. Технології
React Native + Expo для крос-платформності (iOS, Android, веб одним
кодом).

### 13. Етапи роботи
1. Технічне завдання і ескізи — готово.
2. Розробка застосунку покроково з тестуванням.
3. Тестування автором.
4. Публікація для iOS/Android/веб.
5. Монетизація — пізніше, за бажанням.

## Архітектурні рішення

- **Expo SDK + TypeScript**, навігація через **Expo Router** (file-based,
  однаково працює на iOS/Android/web).
- **Офлайн-перший стан**: `zustand` зі збереженням у
  `AsyncStorage` (`@react-native-async-storage/async-storage`) —
  єдине джерело правди локально; хмарна синхронізація (Firebase/Supabase)
  підключається пізніше як окремий шар над тим самим стором, не змінюючи
  публічний API стору.
- **Іконки**: `@expo/vector-icons` (Ionicons).
- Стилі — `StyleSheet.create`, без сторонніх CSS-фреймворків, щоб
  мінімізувати залежності на старті.
- Дані відео (прев'ю/назва/тривалість) на першому етапі — через сервіс
  `services/videoMeta.ts` з можливістю підміни реальним oEmbed/API
  парсингом YouTube/TikTok пізніше.

## Структура проєкту

```
app/                      Expo Router екрани
  _layout.tsx             Кореневий layout (провайдер стору, тема)
  index.tsx               Головний екран (стрічка відео)
  add-video.tsx           Модальний екран додавання відео
  video/[id].tsx          Перегляд відео
  settings.tsx            Налаштування
  tag-editor.tsx          Редактор тега
components/
  VideoCard.tsx           Картка відео у стрічці
  FilterPills.tsx         Пігулки-фільтри статусу
  SearchBar.tsx           Рядок пошуку
  FloatingIsland.tsx       Плаваючий острівець-капсула з 4 кнопками
  TagChip.tsx             Пігулка тега
  TagsDrawer.tsx          Бокове меню тегів
  StatusToggle.tsx        Перемикач статусу (дві пігулки)
store/
  useLibraryStore.ts      Zustand-стор: відео, теги, фільтри, налаштування
types/
  index.ts                Video, Tag, WatchStatus, Settings
constants/
  theme.ts                Кольори, розміри, типографіка
services/
  videoMeta.ts            Отримання прев'ю/назви/тривалості за посиланням
```

## Команди

```
npm install
npm run start     # Expo dev server (вибір платформи: i/a/w)
npm run web       # запуск веб-версії
npm run ios
npm run android
```
